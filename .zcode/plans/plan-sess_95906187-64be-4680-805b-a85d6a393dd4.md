## 第 1 步：朴素写法（反面教材）
展示两种典型错误写法：
- (a) 路由里现 `MemoryRunEventStore()`：事件活不过一个请求；
- (b) 只往 SSE 流推事件、根本不落库：刷新页面后历史消息全没（连 agent 说过的最后一句话都查不到）。
讲清"事件流（实时）"和"事件历史（可查询）"是两件事。

## 第 2 步：6 个麻烦（文档主体，每个都含「场景 / 朴素为什么做不到 / DeerFlow 怎么解决 + 逐行代码」）

- **麻烦 1：刷新页面要看到历史消息（朴素写法做不到）**
  → 解决：进程级单例 + 启动时建一次。代码：`deps.py:299-305` 安装、`make_run_event_store` 工厂（`store/__init__.py`）。讲清 store 是进程级、`_require("run_event_store", ...)` 的 503 兜底（复用姊妹篇 `_require` 逐行讲解，但简短引用）。

- **麻烦 2：seq 必须按 thread 全局单调（不能每个 run 各自从 1 数）**
  → 解决：`seq` 的定义在 `RunEventStore` 接口契约里（`base.py:22-28` 第 2 条保证）。讲为什么不能用 `run_id` 局部序号（前端按 thread 翻页要统一时间轴）。逐行讲 Memory 的 `_next_seq`（`memory.py:33-37`）。

- **麻烦 3：消息 vs 轨迹——同一个接口两种用途（category 区分）**
  → 解决：`category` 字段（message/trace/lifecycle）；`list_messages` 只返回 message、`list_events` 返回全部。逐行讲 Memory 的四张投影（`memory.py:18-30` 的 `_events` / `_messages` / `_events_by_run` / `_messages_by_run`）为什么让两种查询都是 O(log m + page)（bisect），而不是每次重扫全表。

- **麻烦 4：Db 后端怎么保证跨进程 seq 单调——双层锁**
  → 解决：`DbRunEventStore` 的 `put` / `put_batch`（`db.py:129-195`）。
  逐行深讲：
  - 进程内 `asyncio.Lock`（`db.py:30-43`，堵同进程两个协程在 max(seq)→INSERT 之间交错撞 seq）；
  - 跨进程 FOR UPDATE / `pg_advisory_xact_lock`（`db.py:107-127`）——为什么 Postgres 拒绝 `SELECT max(...) FOR UPDATE`（聚合结果不可锁行）、为什么用 `pg_advisory_xact_lock(hashtext(thread_id))` 作为 release-safe 替代；
  - `_user_id_from_context` 软读 + UUID→VARCHAR 强转（`db.py:89-105`，那条 "aiosqlite 绑不了 UUID 到 VARCHAR、worker 会挂" 的注释非常值得逐字讲）；
  - `_truncate_trace` + `_content_to_db`（trace 字节截断 + 结构化 content JSON 序列化）。

- **麻烦 5：多租户隔离——`user_id` / AUTO sentinel**
  → 解决：`AUTO` sentinel 的语义（"未显式传"≠"显式 None"）；`list_messages` 的 `user_id` 参数（`base.py:52-71`）；Db 读路径用 `resolve_user_id` 应用过滤（`db.py` 读方法），Memory 因为单租户默认不隔离。讲为什么写路径是软读（worker 在 contextvar 没设置时返回 None，不报错）。

- **麻烦 6：Jsonl 单进程限制 + 路径安全 + 后端选择冻结**
  → 解决：
  - `JsonlRunEventStore` 的单进程硬限（`jsonl.py:9-12` docstring 明说"多进程会产生重复/非单调 seq"），`asyncio.to_thread` 不堵事件循环（`jsonl.py:14-16`），`list_messages` 必须扫该 thread 全部 run 文件的取舍（`jsonl.py:18-20`），`_SAFE_ID_PATTERN` 防路径穿越（`jsonl.py:38, 51-56`）。
  - `make_run_event_store` 三路分支 + db 后端 fallback（`store/__init__.py:5-23`：db 但没引擎 → 退回 Memory）。
  - **冻结快照**：`deps.py:299-305` 的注释 + `reload_boundary.py:48`——`run_events_config` 和 store 必须成对冻结，`get_run_context`（`deps.py:406-424`）拿的是冻结的 config，绝不让 hot-reload 后的新 config 配上旧 backend 的 store。
